# 撰寫 PRD (Product Requirements Document) 技能

當你需要撰寫 PRD 時，請遵循以下結構：

1. **專案摘要 (Executive Summary)**：簡述功能目的與預期效益。
2. **使用者故事 (User Stories)**：以「身為...我想要...以便於...」的格式列出。
3. **功能需求 (Functional Requirements)**：條列式說明系統需具備的具體功能。
4. **非功能需求 (Non-functional Requirements)**：包含效能、安全性、支援的瀏覽器等。
5. **UI/UX 流程 (User Flow)**：簡述使用者操作的步驟。
6. **API 規格草案 (API Spec Draft)**：列出需要新增或修改的 API 端點。

請使用繁體中文，並且盡量使用 Markdown 的表格或清單來讓版面清晰易讀。
